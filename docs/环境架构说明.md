**分工逻辑**：管事的（NameNode、ResourceManager、HMaster、MySQL、Hive、Kylin）全在 master；
干活的（DataNode、NodeManager、HRegionServer）在 slave。

## 三、为什么要按这个顺序装

组件之间有硬依赖，顺序错了装不起来：

```
JDK  ──►  ZooKeeper  ──►  Hadoop  ──►  HBase  ──►  Hive  ──►  Kylin
         （协调者）      （存储+计算）  （随机读写）  （SQL外壳）（预计算）
              │              │            │
              └──────────────┴────────────┘
                     HBase 要同时用 ZK 和 HDFS
```

- **JDK 第一**：Hadoop、HBase、Hive、Kylin 全是 Java 程序，没有 JVM 一行代码都跑不起来
- **ZooKeeper 第二**：它是协调服务，HBase 启动时第一件事就是去 ZK 注册自己。ZK 没起来，HBase 直接失败
- **Hadoop 第三**：它提供两样东西——HDFS（存数据）和 YARN（管计算资源）。HBase 的数据就存在 HDFS 里
- **HBase 第四**：它自己不做分布式存储，把数据放在 HDFS 上，靠 ZK 做主从选举
- **Hive 第五**：它把 HBase/HDFS 的数据"包一层 SQL 外壳"，元数据存在 MySQL 里
- **Kylin 最后**：它从 Hive 读数据预计算，必须等前面全部就绪

## 四、每个配置文件在说什么

### 4.1 `/etc/profile`（三台）

```bash
export JAVA_HOME=/opt/module/jdk1.8.0_221
export HADOOP_HOME=/opt/module/hadoop
export PATH=$PATH:$HADOOP_HOME/bin:$HADOOP_HOME/sbin
export HBASE_HOME=/opt/module/hbase
```

**作用**：告诉系统"这些程序装在哪"，这样任何目录下敲 `hadoop`、`hbase` 都能找到。

**为什么写死在文件里**：程序互相调用时会启动新的 shell，新 shell 不继承你当前终端的环境变量。写在 `/etc/profile` 里，每个新 shell 都会读到。

> **重要**：`ssh 主机 '命令'` 这种方式启动的 shell **不读** `/etc/profile`。所以远程执行命令时前面要加 `source /etc/profile;`。

### 4.2 ZooKeeper 的 `zoo.cfg`（三台一样，只有 myid 不同）

```properties
tickTime=2000
initLimit=10
syncLimit=5
dataDir=/opt/module/zookeeper/data
clientPort=2181
server.1=master:2888:3888
server.2=slave1:2888:3888
server.3=slave2:2888:3888
```

| 配置 | 含义 |
|---|---|
| `tickTime` | 心跳节拍，2 秒一次 |
| `initLimit` | 从节点初次同步最多等 10 个心跳（20 秒） |
| `syncLimit` | 同步超时 5 个心跳，超了就认为节点挂了 |
| `dataDir` | 数据存哪。**默认是 /tmp，必须改**，否则重启全丢 |
| `clientPort=2181` | HBase、Kylin 都连这个端口找 ZK |
| `server.N=主机:2888:3888` | 三台互相认识。2888 是主从同步，3888 是选主投票 |

`data/myid` 文件里一个数字（1/2/3），告诉 ZK "我是第几号"。和 `server.N` 对应。

### 4.3 Hadoop 的 5 个配置

**`hadoop-env.sh`**
```bash
export JAVA_HOME=/opt/module/jdk1.8.0_221
```
默认是 `export JAVA_HOME=${JAVA_HOME}`，靠读环境变量。但守护进程常在没有环境变量的 shell 里启动，读不到就崩。**写死最稳**。

**`core-site.xml`**
```xml
<property><name>fs.defaultFS</name><value>hdfs://master:9000</value></property>
<property><name>hadoop.tmp.dir</name><value>/opt/module/hadoop/data</value></property>
```
- `fs.defaultFS`：整个集群的入口地址。后面 HBase 的 `hbase.rootdir` 必须和它一致
- `hadoop.tmp.dir`：名字带 tmp，但**不能放 /tmp**。所有运行数据都在这，放 /tmp 重启就没了

**`hdfs-site.xml`**
```xml
<property><name>dfs.replication</name><value>2</value></property>
<property><name>dfs.namenode.secondary.http-address</name><value>master:50090</value></property>
```
- `dfs.replication=2`：每个文件存 2 份。**有几台 DataNode 就设几**，设 3 但只有 2 台会一直报警告
- `secondary.http-address`：默认值是 `0.0.0.0:50090`，启动脚本会把这个地址当主机名去 SSH，连不上。**必须明确写成 master**

**`yarn-site.xml`**
```xml
<property><name>yarn.nodemanager.aux-services</name><value>mapreduce_shuffle</value></property>
<property><name>yarn.resourcemanager.hostname</name><value>master</value></property>
```
- `aux-services`：MapReduce 的 shuffle 服务，漏配会卡住
- `resourcemanager.hostname`：调度器在哪台

**`mapred-site.xml`**
```xml
<property><name>mapreduce.framework.name</name><value>yarn</value></property>
```
告诉 MapReduce"去 YARN 上跑"。不配就走本地模式，看不出集群效果。

**`slaves`**
```
slave1
slave2
```
从节点清单。**默认有 localhost，必须删掉**，否则会在 master 上也起一个 DataNode，架构就乱了。

### 4.4 HBase 的 2 个配置

**`hbase-env.sh`**
```bash
export JAVA_HOME=/opt/module/jdk1.8.0_221
export HBASE_MANAGES_ZK=false
```
- `HBASE_MANAGES_ZK=false` **最关键**：HBase 默认自带一个 ZooKeeper。但你已经有 ZK 在 2181 跑着，两个会抢端口打起来。设成 false 就是"用现成的，别自己开"

**`hbase-site.xml`**
```xml
<property><name>hbase.rootdir</name><value>hdfs://master:9000/hbase</value></property>
<property><name>hbase.cluster.distributed</name><value>true</value></property>
<property><name>hbase.zookeeper.quorum</name><value>master,slave1,slave2</value></property>
```
- `hbase.rootdir`：HBase 的数据实际存在 HDFS 的 `/hbase` 目录下。**HBase 自己不做分布式存储，它借用 HDFS**
- `cluster.distributed=true`：分布式模式（多台），不是单机模式
- `zookeeper.quorum`：去这三台找 ZooKeeper，HBase 的元数据（哪张表在哪个 RegionServer 上）存在 ZK 里

**`regionservers`**
```
slave1
slave2
```
RegionServer 清单，和 Hadoop 的 `slaves` 一个道理。

## 五、这套环境对项目意味着什么

### 5.1 数据怎么流动

```
老师给的 6 个 txt 数据文件（/opt/bi_data/mysql_data）
        │
        ├──► MySQL 的 yiyao 库 ──┬──► Django 大屏取数（李艺淼）
        │                        └──► 后端兜底查询
        │
        └──► HBase 6 张表（/opt/bi_data/hbase_data）
                  │
                  └──► Hive 建外部表指向 HBase（能用 SQL 查）
                            │
                            └──► Kylin 建模型 + Cube（提前算好，查询变毫秒级）
                                      │
                                      └──► SpringBoot 12 个接口
                                                │
                                                └──► Vue 前端 12 张图
```

### 5.2 每层解决什么问题

| 层 | 解决什么 | 如果去掉会怎样 |
|---|---|---|
| HDFS | 把三台机器的硬盘拼成一块 | 数据没地方存 |
| ZooKeeper | 三台机器选出主从、记住谁活着 | HBase 起不来 |
| HBase | 按药品/医院/疾病编号快速取一条记录 | Hive 只能扫全表，慢 |
| Hive | 让不会写 Java 的人能用 SQL 查 | 得写 MapReduce 程序 |
| Kylin | 把统计结果提前算好存着 | 每次查询都要现算，12 张图要转圈很久 |
| MySQL | 存量小、要精确查询的数据 | 后端和大屏都没数据 |

**核心理解**：Kylin 之所以快，是因为它**提前算好了**。代价是"建 Cube"这一步很慢很重（十几分钟起），而且维度配错就得重建。这是整个项目最耗时的环节。

### 5.3 为什么数据要存两份（MySQL 和 HBase）

不是冗余，是两个不同的用途：

- **MySQL**：存全量明细，给 Django 大屏用（大屏直接查 MySQL，不经过 Kylin）
- **HBase**：给 Hive/Kylin 这条大数据链路用，按行键随机读取比 MySQL 快

资料里两条链路本来就分开设计，所以数据要灌两次。

## 六、以后怎么用

### 6.1 每天启动（开机后必须做）

集群启动有严格顺序，**不能乱**：

```bash
# ① 全部节点
/opt/module/zookeeper/bin/zkServer.sh start

# ② master
source /etc/profile
/opt/module/hadoop/sbin/start-all.sh
/opt/module/hadoop/sbin/mr-jobhistory-daemon.sh start historyserver

# ③ master（等 ② 完成再执行）
/opt/module/hbase/bin/start-hbase.sh

# ④ 全部节点
/opt/module/hive/bin/hive --service metastore &
/opt/module/hive/bin/hive --service hiveserver2 &

# ⑤ master（等 ④ 起来）
$KYLIN_HOME/bin/kylin.sh start
```

或用仓库里的脚本：`bash deploy/start-all.sh`

### 6.2 关闭（反向执行）

```bash
$KYLIN_HOME/bin/kylin.sh stop
/opt/module/hbase/bin/stop-hbase.sh
/opt/module/hadoop/sbin/stop-all.sh
/opt/module/zookeeper/bin/zkServer.sh stop
```

**Kylin 必须在 HBase 之前关。** 反过来会因为找不到元数据而报错。

### 6.3 健康检查（三层判断法）

怀疑某个组件有问题时，按这三个层次查，别乱试：

```bash
# ① 进程在不在
jps

# ② 端口在不在听
ss -lntp | grep -E "2181|9000|50070|8088|60010|7070"

# ③ 日志说什么
tail -50 $组件HOME/logs/xxx.log
```

**关键习惯**：`jps` 里出现 `WrapperSimpleApp` 是云平台的监控代理，不是你的组件；出现 `Jps` 是 `jps` 命令自己。

### 6.4 各组件的 Web 界面

| 组件 | 地址 | 看什么 |
|---|---|---|
| HDFS | `http://master:50070` | 存了多少文件、副本状态 |
| YARN | `http://master:8088` | 有哪些计算任务在跑 |
| HBase | `http://master:60010` | 有哪些表、RegionServer 分布 |
| Kylin | `http://master:7070/kylin` | 项目、模型、Cube、构建进度 |

### 6.5 出问题先看哪里

| 现象 | 先查 | 常见原因 |
|---|---|---|
| HMaster 起不来 | `$HBASE_HOME/logs/hbase-root-master-master.log` | ZK 没起、`hbase.rootdir` 地址错、`HBASE_MANAGES_ZK` 没设 false |
| slave 上没有 DataNode | `ssh slave1 'tail -30 .../hadoop-root-datanode-slave1.log'` | 主机名解析失败、SSH 免密失效、磁盘满 |
| Kylin 起不来 | `kylin.sh start` 的输出 | HBase/Hive 没就绪、内存不足 |
| 命令 `command not found` | `echo $HADOOP_HOME` | 没 `source /etc/profile`，或远程执行没加这一句 |
| 端口 `Address already in use` | `jps` | 有旧进程没退出，先 `stop-xxx.sh` |

## 八、必须做的一件事：备份配置

**这套环境 11 月 15 日晚上过期，配置一旦丢失就得重装一遍。**

配置文件都很小（几十 KB），全部备份到 Git 仓库：

```bash
mkdir -p /opt/config_backup
cp /etc/profile /opt/config_backup/
cp -r /opt/module/zookeeper/conf /opt/config_backup/zookeeper_conf
cp -r /opt/module/hadoop/etc/hadoop /opt/config_backup/hadoop_conf
cp -r /opt/module/hbase/conf /opt/config_backup/hbase_conf
tar -czf /opt/config_backup/all_config.tgz /opt/config_backup
ls -lh /opt/config_backup/all_config.tgz
```

把这个 tgz 用 FileZilla 下载到 Windows，再提交到 Git 仓库的 `deploy/config-backup/` 目录。

**为什么重要**：数据文件 (`/opt/bi_data`) 是镜像自带的，重装环境时还在；但**你写的这些配置、`/etc/profile`、Kylin 的 Cube 定义，都是这次做的，丢了就是从零开始**。

## 九、答辩可以怎么说

如果老师问"你们的技术架构"：

> 我们搭的是三节点 Hadoop 集群。master 负责管理：NameNode 管 HDFS 元数据、ResourceManager 管 YARN 资源、HMaster 管 HBase；worker 两台（slave1、slave2）负责实际存储和计算，上面跑 DataNode、NodeManager、HRegionServer。
>
> 协调层用 ZooKeeper 三节点集群，一主两从，保证 HBase 的主从选举和元数据一致性。
>
> 数据链路是：业务数据分两路存储，一路进 MySQL 供大屏和兜底查询，一路进 HBase 供大数据链路；HBase 之上用 Hive 建外部表，用 SQL 的方式访问；再上层用 Kylin 做预计算，把多维分析的结果提前物化成立方体，后端的 12 个接口查询 Kylin 能在毫秒级返回，前端用 Vue 加 ECharts 渲染。
>
> 部署在华为云的实验机上，通过平台的网页终端管理。

这段里每个技术名词都有对应的实际配置，被追问时能说清"为什么这么配"。
