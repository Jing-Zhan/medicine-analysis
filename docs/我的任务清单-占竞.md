## 第 1 步 · 启动集群（T1）

**前置条件**：第 0 步看过 `/opt/module` 里有组件。

**来源**：老师下发的 `资料\医药环境启动`

集群不能一次全起，**有依赖顺序**：ZooKeeper 是协调者，必须先起；HBase 要用 HDFS 存数据，所以 HDFS 得先起；Kylin 要用 Hive 和 HBase，所以它在最后。

```bash
# ① 全部节点（master、slave1、slave2 都执行）
/opt/module/zookeeper/bin/zkServer.sh start

# ② 只在 master
/opt/module/hadoop/sbin/start-all.sh
/opt/module/hadoop/sbin/mr-jobhistory-daemon.sh start historyserver

# ③ 只在 master
/opt/module/hbase/bin/start-hbase.sh

# ④ 全部节点
/opt/module/hive/bin/hive --service metastore &
/opt/module/hive/bin/hive --service hiveserver2 &

# ⑤ 只在 master，等 ④ 起来之后
$KYLIN_HOME/bin/kylin.sh start
```

或者直接用我写好的脚本（它会检查依赖并打印结果）：

```bash
bash deploy/start-all.sh
```

**怎么算成功**

```bash
jps
```

master 上应该能看到：

| 进程名 | 是什么 |
|---|---|
| `QuorumPeerMain` | ZooKeeper |
| `NameNode` | HDFS 的"目录管家" |
| `SecondaryNameNode` | HDFS 的辅助 |
| `ResourceManager` | YARN 的资源调度 |
| `HMaster` | HBase 主节点 |
| `RunJar` | Kylin（名字不直观，看到它基本就是 Kylin） |

slave1 / slave2 上应该有 `DataNode`、`NodeManager`、`HRegionServer`。

**注意**：`jps` 里出现 `Jps` 是正常的，那是 `jps` 命令自己。

**常见失败**

| 现象 | 原因 | 处理 |
|---|---|---|
| HBase 起来又掉了 | ZooKeeper 没起，或 `hbase.rootdir`、`znode.parent` 指错 | 先 `zkServer.sh status` 看 ZooKeeper 活没活 |
| Kylin 起不来 | HBase 或 Hive 没就绪 | `kylin.sh start` 前先确认 `jps` 里有 `HMaster` |
| slave 上没有进程 | 三台机器 hosts 对不上 | 三台都 `cat /etc/hosts` 比对 |

- [ ] 三台 `jps` 进程齐全

## 第 3 步 · 把数据导进 HBase（T2）

**前置条件**：第 1 步完成（HBase 在跑），数据文件已上传到服务器。

**来源**：资料任务 10。**这一段资料里有两个坑，我核实过了。**

### 坑一：目录名带 `_f`，表名不带

老师给的数据目录叫 `AreaInfo_f`、`DrugInfo_f`……，但 **HBase 表名是 `AreaInfo`、`DrugInfo`，没有 `_f`**。写错导入直接失败。

### 建表

```bash
hbase shell

create 'HospInfo','f'
create 'PrescriptionDisease','f'
create 'SectionInfo','f'
create 'DrugInfo','f'
create 'DiseaseInfo','f'
create 'AreaInfo','f'

exit
```

六个表，列族统一叫 `f`。

### 上传到 HDFS

```bash
hadoop fs -mkdir /hbase/table
hadoop fs -put /home/bi_data/hbase_data/* /hbase/table
hadoop fs -ls /hbase/table
```

最后一条应该列出 6 个带 `_f` 的目录。

> 资料正文这里写过 `/opt/bi_data`，但老师给的数据说明里是 `/home/bi_data`。以服务器上 `ls` 出来的实际路径为准。

### 逐表导入

**第一个参数是表名（无 `_f`），第二个是 HDFS 目录（有 `_f`）**：

```bash
hbase org.apache.hadoop.hbase.mapreduce.Import HospInfo /hbase/table/HospInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import PrescriptionDisease /hbase/table/PrescriptionDisease_f
hbase org.apache.hadoop.hbase.mapreduce.Import SectionInfo /hbase/table/SectionInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import DrugInfo /hbase/table/DrugInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import DiseaseInfo /hbase/table/DiseaseInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import AreaInfo /hbase/table/AreaInfo_f
```

`PrescriptionDisease` 有 356MB，**这一条会跑很久**，放晚上挂着。

### 核对

```bash
hbase shell
scan 'AreaInfo', {LIMIT => 3}
count 'PrescriptionDisease'
```

小表几十万行以内 `count` 很快；`PrescriptionDisease` 的 `count` 也可能跑很久，可以先跳过，等 Hive 建好再从 Hive 侧核对。

- [ ] 6 张表建好

- [ ] 6 张表导入完成
- [ ] 小表 `scan` 能看到数据和列名

## 第 4 步 · 验收李艺淼的 Hive（不是你的活，但要你把关）

**前置条件**：他建完 6 张外部表。

**为什么你要管**：Kylin 是从 Hive 取数的。Hive 那层字段错位，Kylin 建得再对，查出来的数也是错的，而且**不会报错**，只是数字不对。这是最难发现的问题。

```bash
hive

select count(*) from bigdata.prescription_diseases;
select count(*) from bigdata.hospital;
select count(*) from bigdata.drug;
select count(*) from bigdata.section;
select count(*) from bigdata.disease;
select count(*) from bigdata.hosp_area;

-- 重点抽查这张
select * from bigdata.disease limit 10;
```

`disease` 这张要特别看：**资料里它的列映射少了一个字段（`f:diseaseType3`），照抄会错位。** 正常应该能看到疾病编码和三级分类，如果整列全是 `NULL` 或者明显串位，就要他改映射重建。

- [ ] 6 张表行数与 HBase 一致
- [ ] `disease` 表字段不为空、不错位

## 第 5 步 · 建 Kylin 立方体（T5）

**前置条件**：第 3 步（HBase）和第 4 步（Hive）都过，并且付悌安的 MySQL 也导完了。

**来源**：资料任务 11。**这里资料有三处要按我说的改。**

### 坑二：项目名必须是 `yiyao`

资料写的是 `bi_yiyao`，但后端配置文件 `application.properties` 里是：

```
kylin.url=jdbc:kylin://master:7070/yiyao
```

项目名对不上，12 个接口全部报"项目不存在"。**用 `yiyao`。**

### 坑三：事实表选复数

资料写 `PRESCRIPTION_DISEASE`（单数），但 Hive 里建的表明明是 `prescription_diseases`（复数），后端 SQL 里也是 `BIGDATA.PRESCRIPTION_DISEASES`。**下拉里选复数的那个。**

### 操作顺序

1. 浏览器打开 `http://<ip>:7070/kylin`，`ADMIN` / `KYLIN`
2. 新建项目，名字 `yiyao`
3. 导入数据源，勾选 `bigdata` 库下所有表
4. `Models → New → New Model`，名字随便（`bi_model`）
5. 事实表选 `BIGDATA.PRESCRIPTION_DISEASES`
6. `Add Lookup Table` 加 5 张关联表，关联条件：

   | 从表 | 关联字段 |
   |---|---|
   | `SECTION` | `M_SECTION = SECTION.SECTION2` |
   | `DISEASE` | `M_DIAGNOSTIC = DISEASE.DISEASE_TYPE13` |
   | `DRUG` | `M_DRUG = DRUG.DRUG` |
   | `HOSPITAL` | `HOSP_ID = HOSPITAL.HOSP_ID` |
   | `HOSP_AREA` | `HOSPITAL.HOSP_ID = HOSP_AREA.HOSP_ID` |

7. 维度全选，**度量只选 `PRICE` 和 `AMOUNT`**
8. `New Cube`，选刚才的模型，名字随便（`bi_cube`）
9. 加维度：全选所有字段，**删掉重复的 `HOSP_ID`**（会出现两个，第 28 行和第 35 行）
10. 加两个度量：`SUM(PRICE)`、`SUM(AMOUNT)`
11. 后面几步默认，`Save`
12. 列表里状态是 `DISABLED`，点 `Action → Build`
13. **等**。资料说 10 分钟左右，数据量大可能更久。在 `Monitor` 里看进度

### 验证

构建完成后，在 `Insight` 里跑：

```sql
SELECT COUNT(*) FROM BIGDATA.PRESCRIPTION_DISEASES
```

能出数字就说明 Cube 可用。

**再跑一条验证关联没坏**（这条能提前暴露第 4 步的字段错位问题）：

```sql
SELECT DISEASE.DISEASE_TYPE13, COUNT(*)
FROM BIGDATA.PRESCRIPTION_DISEASES AS P
LEFT JOIN BIGDATA.DISEASE AS DISEASE
ON P.M_DIAGNOSTIC = DISEASE.DISEASE_TYPE13
GROUP BY DISEASE.DISEASE_TYPE13
ORDER BY 2 DESC
LIMIT 10
```

如果第一列全是 `null`，说明疾病表关联失败，回第 4 步查 Hive。

- [ ] 模型建好，5 张关联表都挂上

## 附：几个概念速查

你不需要精通，但要知道它们是干什么的，出问题时才能判断是哪一层。

| 组件 | 一句话 | 挂了会怎样 |
|---|---|---|
| **ZooKeeper** | 集群的"协调员"，负责选主和状态同步 | HBase 起不来 |
| **HDFS** | 把三台机器的硬盘拼成一块大的 | 所有数据没了 |
| **HBase** | 能按编号快速取数据的数据库（NoSQL） | Hive 查不到数 |
| **Hive** | 给 HDFS 数据套一层 SQL 外壳 | Kylin 无数据可建 |
| **Kylin** | 提前把统计结果算好存着，查的时候直接拿 | 后端 12 个接口全废 |
| **MySQL** | 小数据量的关系库 | 后端和大屏都取不到数 |
| **YARN** | 管计算资源 | 影响不大 |

**关键理解**：Kylin 之所以快，是因为它提前算好了。代价是"建 Cube"这一步很慢很重，而且一旦维度配错就得重建。所以第 5 步才被标成整个项目的瓶颈。
