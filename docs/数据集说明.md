```bash

# 2. 数据文件放到脚本约定路径
mkdir -p /home/bi_data/mysql_data
# 将上述 6 个 txt 上传到该目录

# 3. 执行导入

# 4. 核对行数
```

## 二、HBase 数据

来源：`目标适应症及用药数据分析系统（分组）\项目数据\hbase_data\hbase_data\`

| 目录 | 大小 | 目标表 |
| --- | --- | --- |
| `AreaInfo_f` | 796KB | `AreaInfo` |
| `DiseaseInfo_f` | 16MB | `DiseaseInfo` |
| `DrugInfo_f` | 103MB | `DrugInfo` |
| `HospInfo_f` | 547KB | `HospInfo` |
| `PrescriptionDisease_f` | 356MB | `PrescriptionDisease` |
| `SectionInfo_f` | 63KB | `SectionInfo` |

每个目录内是 `part-m-00000` 形式的 **SequenceFile**（文件头 `SEQ`），需先上传 HDFS，再用 HBase 自带工具导入。

> **注意：目录名带 `_f` 后缀，HBase 表名不带。** 这是资料里两处容易看岔的地方，写错表名导入会直接失败。

### 建表与导入（资料原文步骤）

```bash
# 1. 建表，列族统一为 f
hbase shell
create 'HospInfo','f'
create 'PrescriptionDisease','f'
create 'SectionInfo','f'
create 'DrugInfo','f'
create 'DiseaseInfo','f'
create 'AreaInfo','f'
exit

# 2. 在 HDFS 上建目录并上传（注意源目录用服务器上的实际路径）
hadoop fs -mkdir /hbase/table
hadoop fs -put /home/bi_data/hbase_data/* /hbase/table
hadoop fs -ls /hbase/table

# 3. 逐表导入：第一个参数是表名（无 _f），第二个是 HDFS 目录（有 _f）
hbase org.apache.hadoop.hbase.mapreduce.Import HospInfo /hbase/table/HospInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import PrescriptionDisease /hbase/table/PrescriptionDisease_f
hbase org.apache.hadoop.hbase.mapreduce.Import SectionInfo /hbase/table/SectionInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import DrugInfo /hbase/table/DrugInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import DiseaseInfo /hbase/table/DiseaseInfo_f
hbase org.apache.hadoop.hbase.mapreduce.Import AreaInfo /hbase/table/AreaInfo_f

# 4. 核对
hbase shell
scan 'AreaInfo', {LIMIT => 3}
count 'PrescriptionDisease'
```

导入前确认磁盘与 HDFS 空间：

```bash
df -h /home
hdfs dfs -df -h
```

## 四、数据本身的几个特征（看图表时必须知道）

以下都是**实测出来的数据性质**，不是缺陷，但会直接影响图表长什么样、指标能不能对上，答辩时大概率被问。

### 4.1 只覆盖 2008 年 12 月一个月

```sql
SELECT year_month, COUNT(*) FROM prescription_diseases GROUP BY year_month;
-- 200812  1000000
```

100 万行全部是同一个月份。`record_id` 的前 6 位也恒为 `200812`。

**影响：** 「城市等级竞争图表」的时间轴只有一个刻度 `200812`，堆叠柱只有一根。

**这里修正过原项目的一个问题：** 原 SQL 用 `'201' + SUBSTRING(record_id, CHAR_LENGTH(record_id))` 当「年份」，也就是取流水号的最后一位拼上去。而实测 `record_id` 末位是 `0~9` 各 10 万行完全均匀，拼出来的「2010~2019 年」跟时间毫无关系。现已改为读取真实的 `year_month` 字段。

### 4.2 年龄只有 40~89 岁，且每个年龄恰好 2 万人

```sql
SELECT MIN(m_age), MAX(m_age), COUNT(DISTINCT m_age), COUNT(*) FROM prescription_diseases;
-- 40  89  50  1000000
```

50 个年龄值 × 2 万 = 100 万，分布完全均匀。

**影响：** 「不同年龄患病比例分析」的每个十年段固定是 20 万人。

### 4.3 性别只有 `10` / `20` 两个取值，约 1:1，且与年龄无关

```sql
SELECT m_sex, COUNT(*) FROM prescription_diseases GROUP BY m_sex;
-- 10  500222
-- 20  499778
```

`10` 对应男、`20` 对应女（后端 DTO 直接按这两个字符串判断）。

按十年段拆分后差异极小：

| 年龄段 | 男 | 女 | 男占比 | 女占比 |
| --- | --- | --- | --- | --- |
| 40-50 | 99777 | 100211 | 9.9777% | 10.0211% |
| 50-60 | 99908 | 99989 | 9.9908% | 9.9989% |
| 60-70 | 100351 | 99951 | 10.0351% | 9.9951% |
| 70-80 | 100209 | 99583 | 10.0209% | 9.9583% |
| 80-90 | 99977 | 100044 | 9.9977% | 10.0044% |

**影响：** 该图每个年龄段的两根柱子高度几乎一样，四舍五入到一位小数后就是两个完全相同的数。

> **另外修正过原项目的一个问题：** 原 SQL 的性别是拿 `CASE WHEN mod(年龄,2)>0 THEN 10 ELSE 20 END` **从年龄奇偶编出来的**，不是真实性别。现改为读取真实的 `m_sex`。改完之后图上看起来没变化，因为数据里性别本来就接近 1:1——但两处差别会体现出来：按性别拆分后的计数从 20204 变成 10162，说明真的按两个性别各算了一遍。

### 4.4 有 1164 行的 `hosp_id` 在维表里找不到

```sql
SELECT COUNT(*) FROM prescription_diseases p JOIN t_view_areas a ON p.hosp_id = a.hosp_id;
-- 998836
```

100 万减去 998,836 等于 **1,164** 行。所有 SQL 都带 `INNER JOIN` 区域表，这 1164 行会被过滤掉。

**影响：** 概览卡片的「处方总数」是 1,000,000（`COUNT(*)`，不带 JOIN），而各分布图加起来是 998,836。两个数字不一样不是算错，是口径不同。

### 4.5 维表文本字段末尾带回车符、药品码带序号后缀

- `t_view_section.section_name1` 实际值形如 `预防保健科\r`（16 字节 / 6 字符）
- `prescription_diseases.m_drug` 形如 `DM0000178036_2`，而 `t_view_drug.drug` 是 `DM0000178036`

前者已用 `REPLACE(..., CHAR(13), '')` 清洗（见《部署与验收说明》3.2）；后者用生成列 `drug_code` 去后缀并建索引（同 3.1）。
