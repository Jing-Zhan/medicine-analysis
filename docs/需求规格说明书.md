# 需求规格说明书

> 项目：目标适应症及用药数据分析系统  
> 编制：杨博文  
> 日期：2026-11-12

## 1 系统概述

系统以 6 个原始 txt 文件（约 240MB）为数据源，建立 MySQL 明细库和大数据两条链路：MySQL 直接支撑可视化大屏；HDFS 经 Hive 外部表进入 Kylin Cube，再由 SpringBoot 提供 12 个接口，Vue 前端完成 BI 分析展示。系统面向普通用户提供浏览器访问，无需登录；管理员负责集群启动、数据导入、服务部署与日常巡检。HBase 在本方案中承担 Kylin 元数据与 Cube 实体的存储职责。

```text
原始数据（6 个 txt 文件，约 240MB）
      │
      ├──► MySQL（明细库，100 万行）──────────► 可视化大屏
      │
      └──► HDFS ──► Hive 外部表 ──► Kylin Cube ──► SpringBoot 12 接口 ──► Vue 前端
```

## 2 功能需求（12 条）

| 编号 | 功能名称 | 接口路径 | 需求描述 | 数据来源 | 验收标准 |
|---|---|---|---|---|---|
| FR-01 | 城市等级竞争分析 | `/home/citylevel` | 按城市等级统计处方数量与用药金额，反映不同等级城市的医药消费能力差异 | MySQL | HTTP 200；`data` 非空；包含 `cityLevel`、`recordCnt`、`totalAmount` |
| FR-02 | 年龄患病比例分析 | `/home/age` | 按年龄段统计患病人数及占总体比例，反映不同年龄人群的患病分布特征 | Kylin | HTTP 200；`data` 非空；包含 `age`、`recordCnt`、`ratio` |
| FR-03 | 销售金额 Top10 分析 | `/home/top10` | 按销售金额对药品排序并取前十名，反映主力品种及其销售贡献 | MySQL | HTTP 200；`data` 长度为 10；包含 `drugCode`、`drugName`、`totalAmount`；按金额降序 |
| FR-04 | 各省份销量分析 | `/home/province` | 按省份统计处方数量与用药金额，支持不同区域市场的横向对比 | MySQL | HTTP 200；`data` 非空；包含 `provinceName`、`recordCnt`、`totalAmount` |
| FR-05 | 联合用药分析 | `/disease/union` | 统计处方中多个诊断编码同时出现的频次，识别常见的合并症组合 | MySQL | HTTP 200；`data` 非空；包含 `combo`、`recordCnt` |
| FR-06 | 药品组合分析 | `/disease/drug` | 统计同一处方中包含的药品数量分布，识别联合用药习惯 | MySQL | HTTP 200；`data` 非空；包含 `drugCntPerPrescription`、`prescriptionCnt` |
| FR-07 | 疾病年龄分布分析 | `/disease/age` | 按疾病与年龄段交叉统计处方数量，反映不同疾病的易感人群 | Kylin | HTTP 200；`data` 非空；包含 `diseaseCode`、`ageGroup`、`recordCnt` |
| FR-08 | 科室分布分析 | `/disease/section` | 按科室统计处方数量与用药金额，反映各科室的用药规模 | Kylin | HTTP 200；`data` 非空；包含 `section`、`recordCnt`、`totalAmount` |
| FR-09 | 药品覆盖城市分析 | `/drug/cities` | 统计每种药品覆盖的城市数量，反映药品的市场覆盖广度 | MySQL | HTTP 200；`data` 非空；包含 `drugCode`、`cityCnt` |
| FR-10 | 药品覆盖医院分析 | `/drug/hospital` | 统计每种药品覆盖的医院数量，反映药品的渠道渗透率 | MySQL | HTTP 200；`data` 非空；包含 `drugCode`、`hospCnt` |
| FR-11 | 药品对应适应症分析 | `/drug/diseases` | 统计每种药品关联的诊断编码及频次，反映药品的实际用药方向 | MySQL | HTTP 200；`data` 非空；包含 `drugCode`、`diseaseCode`、`diseaseName`、`recordCnt` |
| FR-12 | 药品科室分布分析 | `/drug/section` | 按药品与科室交叉统计用量，反映各科室的用药偏好 | MySQL | HTTP 200；`data` 非空；包含 `drugCode`、`section`、`recordCnt` |

**通用验收要求**：

- 接口返回 HTTP 200，响应体中 `code` 为 200；
- 正常参数下 `data` 为非空数组，无匹配数据时返回空数组 `[]`，不得报错；
- 单次接口响应时间小于 3 秒；
- 返回内容中文不乱码。

## 3 大屏功能需求（5 条）

| 编号 | 功能名称 | 需求描述 | 图表类型 | 验收标准 |
|---|---|---|---|---|
| SR-01 | 省份病例数与用药金额地图 | 中国地图按省份着色，展示各省病例数与用药金额，鼠标悬浮查看具体数值 | 地图 | 地图正常渲染；各省份有颜色深浅差异；悬浮显示省份名、病例数、金额 |
| SR-02 | 用药 Top10 排行 | 展示用药金额最高的 10 种药品，按金额从高到低排列 | 横向柱状图 | 渲染 10 根柱子；药品名从高到低排列；数值与基准值一致 |
| SR-03 | 用药分布 Top10 | 展示用药数量最多的 10 种药品及其占比 | 饼图 | 渲染 10 个扇区；图例显示药品名；占比合计约 100% |
| SR-04 | 病症出现次数 Top10 | 展示出现频次最高的 10 种诊断及其次数 | 横向柱状图 | 渲染 10 根柱子；诊断名与次数清晰可见 |
| SR-05 | 药物关联关系 | 展示经常同时出现的药品组合关系，节点表示药品、连线表示共现 | 关系图 / 桑基图 | 节点与连线正常渲染；节点名称清晰；无脚本报错 |

**大屏通用验收要求**：

- 页面可正常打开，不白屏、无 JavaScript 报错；
- 图表在 1920×1080 分辨率下布局完整；
- 中文不乱码，数值与基准值核对一致；
- 页面加载与图表刷新时间小于 3 秒。
