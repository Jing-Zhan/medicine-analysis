# 日志与截图采集说明

本文档用于采集项目真实运行日志与页面截图，供汇报材料与验收文档使用。

环境是实训平台提供的虚拟机，通过平台界面进入终端，不使用 SSH 工具。
全部命令在 master 节点执行，账号为 root。

采集过程只读，不修改数据库内容，也不重启集群以外的进程。
唯一涉及写入的操作是第四节建两张聚合表，如果表已存在，该节可以跳过。

## 二、打开终端

进入实训平台实验界面，在节点列表里选 master，点终端或命令行入口，会直接进入命令行。

不要尝试 SSH 连接，平台虚拟环境不开放这个端口。

进入后先确认身份与节点对不对。

```bash
hostname
hostname -I
whoami
```

预期第一行是 `master`，第二行包含 `192.168.207.179`，第三行是 `root`。
提示符应该是 `[root@master ~]#` 这种形式。

平台终端有一个特点：页面关闭或长时间无操作会断开，正在跑的长命令可能中断。
第五节脚本跑完约 3 到 6 分钟，执行期间不要关闭页面，也不要切走太久。

## 三、启动环境

### 3.1 一条命令拉起全部服务

```bash
bash /opt/start-all.sh
```

这条脚本做三件事：检测六个集群组件端口，没起来的拉起；启动后端与 Django 大屏；跑一遍自检并逐个打印结果。

执行时间约 1 到 3 分钟。如果集群本来就在跑，十几秒就结束。

### 3.2 怎么看结果

脚本末尾会打印五个访问地址。逐项确认下面三行是否都是 `[ OK ]`。

```
  [ OK ] MySQL 3306，处方表 1000000 行
  [ OK ] /home/overview 返回 200
  [ OK ] 大屏取数正常（db: true）
```

出现 `[FAIL]` 时按提示看对应日志，先不要往下做。

```bash
tail -50 /tmp/yiyao.log
tail -30 /tmp/screen.log
tail -30 /tmp/start-cluster.log
```

### 3.3 确认页面能打开

在 Windows 浏览器里打开下面三个地址，能出图再继续。

```
http://192.168.207.179:83/#/home
http://192.168.207.179:83/#/disease
http://192.168.207.179:83/#/drug
```

首页四张图与两张分析页都要能显示数据，不要停留在加载中。

## 四、补充建表

科室用药结构对比依赖两张表，先查是否已存在。

```bash
mysql -uroot -p123456 yiyao -N -e "
SELECT table_name FROM information_schema.tables
WHERE table_schema='yiyao' AND table_name IN ('agg_section_drug','agg_cat_drug');"
```

如果输出两行表名，说明已经建好，跳过本节。
如果一行都没有，执行建表脚本。

```bash
cd /home/medicine-analysis
time mysql -uroot -p123456 yiyao < deploy/sql/agg_structure.sql
```

预期 1 到 2 分钟，末尾会打印两张表的行数与前五个科室的结构对比。

把这一步的终端输出留着，第 08 张截图就是它。

## 五、一键采集日志

把下面整段复制粘贴到平台终端，会生成一个采集脚本并执行。

```bash
mkdir -p ~/deliver/logs
cat > /tmp/collect-logs.sh <<'EOF'
#!/bin/bash
set -u
OUT=$HOME/deliver/logs
mkdir -p "$OUT"
PASS=123456

echo "采集时间 $(date '+%F %T')" > "$OUT/00-说明.log"
echo "主机 $(hostname -I | awk '{print $1}')" >> "$OUT/00-说明.log"

# 01 一键启动与自检
bash /opt/start-all.sh > "$OUT/01-start-all.log" 2>&1

# 02 状态检查
bash /opt/env-status.sh > "$OUT/02-env-status.log" 2>&1

# 03 Cube 信息
python3 /opt/cube_info.py > "$OUT/03-cube-info.log" 2>&1

# 04 数据基准值
python3 /opt/dump_baseline.py > "$OUT/04-baseline.log" 2>&1

# 05 13 个接口耗时
{
  echo "接口耗时采集 $(date '+%F %T')"
  echo ""
  for u in /home/overview /home/citylevel /home/age /home/top10 /home/province \
           /disease/union /disease/drug /disease/age /disease/section \
           /drug/cities /drug/hospital /drug/diseases /drug/section ; do
    out=$(curl -s -o /dev/null -w '%{http_code} %{time_total}' --max-time 180 "http://localhost:83$u")
    code=${out%% *}
    t=${out##* }
    printf '%-22s HTTP=%s  耗时 %s 秒\n' "$u" "$code" "$t"
  done
} > "$OUT/05-api-timing.log" 2>&1

# 06 表行数
{
  echo "业务表与聚合表行数"
  echo ""
  for t in prescription_diseases agg_disease_total agg_drug_total \
           agg_disease_drug agg_pres_drug agg_section_drug agg_cat_drug ; do
    n=$(mysql -uroot -p$PASS -N -B yiyao -e "SELECT COUNT(*) FROM $t;" 2>/dev/null)
    printf '%-24s %s\n' "$t" "${n:-表不存在}"
  done
} > "$OUT/06-table-counts.log" 2>&1

# 07 索引清单
mysql -uroot -p$PASS -B yiyao -e "
SELECT TABLE_NAME, INDEX_NAME, GROUP_CONCAT(COLUMN_NAME ORDER BY SEQ_IN_INDEX) AS COLS
FROM information_schema.STATISTICS
WHERE TABLE_SCHEMA='yiyao' AND INDEX_NAME LIKE 'idx\_%'
GROUP BY TABLE_NAME, INDEX_NAME ORDER BY TABLE_NAME;" > "$OUT/07-indexes.log" 2>&1

# 08 组件版本
{
  echo "== java =="      ; java -version 2>&1 | head -3
  echo "== python =="    ; python3 -V 2>&1
  echo "== hadoop =="    ; hadoop version 2>/dev/null | head -2
  echo "== hive =="      ; hive --version 2>/dev/null | head -2
  echo "== hbase =="     ; hbase version 2>/dev/null | head -2
  echo "== mysql =="     ; mysql --version 2>&1
  echo "== os =="        ; cat /etc/redhat-release 2>/dev/null
  echo "== kernel =="    ; uname -r
} > "$OUT/08-versions.log" 2>&1

# 09 HDFS 目录
hdfs dfs -ls /bi_data/mysql > "$OUT/09-hdfs.log" 2>&1

# 10 后端日志
tail -50 /tmp/yiyao.log > "$OUT/10-yiyao-log.log" 2>&1

# 11 大屏日志
tail -30 /tmp/screen.log > "$OUT/11-screen-log.log" 2>&1

# 12 部署目录
tree -L 2 -d /home/medicine-analysis > "$OUT/12-deploy-tree.log" 2>&1 \
  || ls -R /home/medicine-analysis | head -60 > "$OUT/12-deploy-tree.log" 2>&1

# 13 接口原始返回片段
{
  for u in /home/overview "/disease/burden?level=11" /drug/overview \
           "/drug/attribute?type=form_name1" "/disease/structure?limit=5" ; do
    echo "===== $u ====="
    curl -s --max-time 180 "http://localhost:83$u" | head -c 900
    echo ""
    echo ""
  done
} > "$OUT/13-api-samples.log" 2>&1

echo "采集完成，文件数 $(ls -1 "$OUT" | wc -l)"
EOF
bash /tmp/collect-logs.sh
```

整段执行约 3 到 6 分钟，最后一行会打印采集到的文件数，应该是 14，包含一份说明文件。

### 5.1 核对

```bash
ls -lh ~/deliver/logs
```

逐个确认文件大小不等于 0。重点看三个文件的内容是否正确。

```bash
cat ~/deliver/logs/05-api-timing.log
```

预期 13 行，每行都是 `HTTP=200`，耗时在 0.6 到 16 秒之间。

```bash
cat ~/deliver/logs/06-table-counts.log
head -30 ~/deliver/logs/01-start-all.log
```

`06` 里 `prescription_diseases` 应该是 1000000。`01` 里五阶段的 `[ OK ]` 行都应在。

### 5.2 某一个文件是空的怎么办

脚本里每条都带了 `2>&1`，空文件通常说明命令本身不存在。单独跑一遍看报错。

```bash
python3 /opt/cube_info.py
mysql -uroot -p123456 yiyao -e "SELECT 1;"
```

修好之后重跑整个脚本即可，脚本会覆盖同名文件。

## 七、把日志取到本地

截图本来就在 Windows 上。日志在服务器上，用下面的办法取下来。

### 7.1 临时开一个下载服务

在平台终端里执行，把日志目录临时发布成一个网页。

```bash
cd ~/deliver
python3 -m http.server 8899 > /tmp/http-download.log 2>&1 &
sleep 2
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8899/
```

最后一行返回 `200` 说明服务起来了。

### 7.2 在浏览器里下载

先在服务器上打一个压缩包。

```bash
tar czf ~/deliver/logs-$(date +%m%d).tar.gz -C ~/deliver logs
ls -lh ~/deliver/logs-*.tar.gz
```

然后浏览器打开下面地址，点压缩包下载。

```
http://192.168.207.179:8899/
```

### 7.3 下载完立刻关掉

```bash
pkill -f "http.server 8899"
curl -s -o /dev/null -w '%{http_code}\n' --max-time 3 http://localhost:8899/
```

第二行返回 `000` 表示端口已关闭。这一步必须做，不要让它一直开着。

### 7.4 平台自带导出优先

如果实训平台界面提供文件导出或文件浏览功能，优先用平台自带的方式取文件，不用开下载服务。
平台自带的路径通常比临时 HTTP 服务更稳妥。

### 7.5 实在取不下来

把三份最关键的日志内容复制出来，直接发到群里，不要发截图。

```bash
cat ~/deliver/logs/05-api-timing.log
cat ~/deliver/logs/06-table-counts.log
sed -n '1,40p' ~/deliver/logs/01-start-all.log
```

## 九、常见问题

**平台终端断开，脚本跑到一半停住**

重新执行第五节的整段命令即可，脚本会覆盖旧文件。
执行期间不要关闭平台页面。

**脚本重复执行会不会出问题**

启动脚本本身可反复执行，已在跑的进程会跳过，不会重复拉起。

**83 端口被占用导致新接口没生效**

`start-all.sh` 会比较 jar 与进程的修改时间，jar 更新就自动重启，正常情况下不需要手工处理。
如果仍然返回 404，手工执行下面两条。

```bash
pkill -f yiyao-0.0.1-SNAPSHOT.jar
sleep 3
bash /opt/start-all.sh
```

**接口返回 500 或返回内容为空**

先看后端日志最后 50 行，一般是 SQL 报错。

```bash
tail -50 /tmp/yiyao.log
```

把报错整段发给组长，不要自行改代码或改数据库。

**下载服务的地址打不开**

确认第 7.1 步最后返回 200，确认浏览器访问的是 `192.168.207.179` 而不是 `localhost`。
平台如果对端口有限制，改用 7.4 节的平台导出功能。

**截图里出现加载中或空白图**

图表依赖接口返回，百万行聚合最慢十几秒。等页面稳定不再变化再截，必要时刷新一次。

**截图模糊**

浏览器缩放保持 100%，不要用系统放大镜或截图工具放大，按原始分辨率截。

**是否需要停服务**

不需要。采集完成后服务保持运行状态即可。
